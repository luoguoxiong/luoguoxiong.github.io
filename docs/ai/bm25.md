# BM25 检索算法详解：从原理到零依赖实现

> BM25 是信息检索领域最经典的排序算法之一，也是 Elasticsearch、Lucene 的默认评分算法。本文从公式推导到代码实现，带你彻底理解 BM25。

## 一、为什么需要 BM25

假设你有一堆文档，用户输入一个关键词，你怎么找到最相关的文档？

最朴素的思路是**词频统计**：哪个文档包含这个词的次数最多，就返回哪个。但这有明显问题：

- 一个 10000 字的文档出现 5 次「React」，和一个 50 字的文档出现 3 次「React」，哪个更相关？
- 一个所有文档都出现的词（如「的」「the」），它的出现次数能代表相关性吗？

BM25（Best Matching 25）就是为解决这两个问题而生的。它通过两个核心机制来优化排序：

1. **IDF（逆文档频率）**：出现得越广泛的词，权重越低
2. **文档长度归一化**：对长文档做惩罚，避免长文档靠词频刷分

## 二、BM25 公式拆解

BM25 的打分公式：

```
score(q, d) = Σ_t idf(t) × tf(t,d) × (k1 + 1) / (tf(t,d) + k1 × (1 - b + b × |d| / avgdl))
```

其中 `idf(t)` 为：

```
idf(t) = ln((N - df(t) + 0.5) / (df(t) + 0.5) + 1)
```

看起来复杂，但拆开后很直观。下面逐个解释。

### 2.1 IDF：词的重要性

```
idf(t) = ln((N - df(t) + 0.5) / (df(t) + 0.5) + 1)
```

| 符号 | 含义 |
|------|------|
| N | 文档总数 |
| df(t) | 包含词 t 的文档数 |
| idf(t) | 词 t 的逆文档频率 |

- 一个词在**所有文档**都出现（`df = N`），IDF 趋近最小值，说明它没有区分度
- 一个词只在**少数文档**出现（`df` 很小），IDF 很大，说明它是关键词

```
// 10 篇文档，词 t 出现在 8 篇中（很常见）
idf = ln((10 - 8 + 0.5) / (8 + 0.5) + 1) = ln(1.294) ≈ 0.26

// 10 篇文档，词 t 只出现在 1 篇中（很稀有）
idf = ln((10 - 1 + 0.5) / (1 + 0.5) + 1) = ln(7) ≈ 1.95
```

稀有词的权重是常见词的 **7.5 倍**。

### 2.2 TF 饱和：词频不能无限增长

```
tf_saturation = tf(t,d) × (k1 + 1) / (tf(t,d) + k1 × ...)
```

分子的结构 `tf × (k1 + 1)` 和分母的 `tf + k1 × ...` 构成一个**渐近饱和**函数：

- tf = 0 时，贡献为 0
- tf 趋近无穷时，贡献趋近 `k1 + 1`（不会无限增长）

**k1（默认 1.5）** 控制饱和速度。k1 越大，词频的影响越持久；k1 越小，饱和越快（一次出现就够了）。

```
k1 = 1.5 时：
  tf=1 -> 贡献 ≈ 1.6 × idf
  tf=2 -> 贡献 ≈ 2.5 × idf
  tf=5 -> 贡献 ≈ 3.5 × idf   （5次只比2次多40%）
  tf=100 -> 贡献 ≈ 2.5 × idf  （趋近上限）
```

### 2.3 文档长度归一化：惩罚长文档

```
(1 - b + b × |d| / avgdl)
```

| 符号 | 含义 |
|------|------|
| \|d\| | 当前文档长度（token 数） |
| avgdl | 所有文档的平均长度 |
| b | 长度归一化强度（默认 0.75） |

- 文档比平均长（`|d| > avgdl`），分母变大，分数降低
- 文档比平均短（`|d| < avgdl`），分母变小，分数升高
- b = 0 时完全不考虑长度；b = 1 时完全按长度比例

**b（默认 0.75）** 是经验值，在大多数场景下效果最好。

### 2.4 完整公式再理解

把三个部分拼起来：

```
score = Σ [ IDF的重要性 ] × [ TF的饱和增长 ] / [ 长度归一化惩罚 ]
         ↑ 稀有词权重大      ↑ 词频有上限      ↑ 长文档被惩罚
```

## 三、倒排索引：让检索变快

如果每次检索都遍历所有文档算 BM25，性能会随文档数线性下降。倒排索引是解决这个问题的关键。

### 3.1 正排 vs 倒排

```
正排索引（文档 -> 词）：
  doc1 -> [React, TypeScript, Hooks]
  doc2 -> [Vue, TypeScript, Composition]
  doc3 -> [React, Redux, Middleware]

倒排索引（词 -> 文档）：
  React       -> {doc1, doc3}
  TypeScript  -> {doc1, doc2}
  Hooks       -> {doc1}
  Vue         -> {doc2}
  Redux       -> {doc3}
```

检索时只需查倒排表，找到 query 中每个词对应的文档集合，然后只对这些文档算分。

### 3.2 代码实现

agentpack-memory 的 [bm25.ts](file:///Users/kye/Documents/ai/agentpack/packages/agentpack-memory/src/retrieval/bm25.ts) 用两个 Map 维护正排和倒排索引：

```typescript
export class BM25Index {
  private k1: number;
  private b: number;
  /** 正排：文档集合（id -> 文档信息） */
  private docs = new Map<string, DocEntry>();
  /** 倒排表：token -> 文档 id 集合 */
  private inverted = new Map<string, Set<string>>();
  private totalLength = 0;

  /** 平均文档长度 */
  private get avgdl(): number {
    return this.docs.size === 0 ? 0 : this.totalLength / this.docs.size;
  }
}
```

`DocEntry` 存储文档的 tokens、长度和词频表：

```typescript
interface DocEntry {
  id: string;
  tokens: string[];
  length: number;
  tf: Map<string, number>;  // 词频表：token -> 出现次数
}
```

### 3.3 添加文档

```typescript
add(id: string, tokens: string[]): void {
  // 同 id 覆盖：先移除旧的倒排
  if (this.docs.has(id)) this.remove(id);

  // 构建词频表
  const tf = new Map<string, number>();
  for (const t of tokens) tf.set(t, (tf.get(t) ?? 0) + 1);

  // 正排：存文档
  this.docs.set(id, { id, tokens, length: tokens.length, tf });
  this.totalLength += tokens.length;

  // 倒排：每个 token 指向这个文档
  for (const t of tf.keys()) {
    let set = this.inverted.get(t);
    if (!set) {
      set = new Set();
      this.inverted.set(t, set);
    }
    set.add(id);
  }
}
```

关键点：**只遍历词频表的 key**（去重后的 token），而不是原始 tokens 数组，避免重复添加倒排项。

### 3.4 检索：只扫描命中文档

```typescript
search(queryTokens: string[], limit = 10): Array<{ id: string; score: number }> {
  const N = this.docs.size;
  const avgdl = this.avgdl;
  const scores = new Map<string, number>();

  for (const t of queryTokens) {
    // 只查倒排表中包含这个词的文档
    const set = this.inverted.get(t);
    if (!set || set.size === 0) continue;

    const df = set.size;
    const idf = Math.log((N - df + 0.5) / (df + 0.5) + 1);

    for (const docId of set) {
      const doc = this.docs.get(docId);
      const tf = doc.tf.get(t) ?? 0;
      if (tf === 0) continue;

      // BM25 打分公式
      const denom = tf + this.k1 * (1 - this.b + (this.b * doc.length) / (avgdl || 1));
      const contrib = (idf * (tf * (this.k1 + 1))) / (denom || 1);
      scores.set(docId, (scores.get(docId) ?? 0) + contrib);
    }
  }

  // 按分数降序，取 top-N
  return [...scores.entries()]
    .sort((a, b) => b[1] - a[1])
    .slice(0, limit);
}
```

**性能优势**：假设有 10000 篇文档，query 有 3 个词，每个词出现在 50 篇文档中。传统遍历要算 10000 次分数，倒排索引只需要算最多 150 次（3 × 50），减少了 **98.5%** 的计算量。

## 四、分词器：中英文混合的处理

BM25 的效果取决于分词质量。agentpack-memory 的 [tokenizer.ts](file:///Users/kye/Documents/ai/agentpack/packages/agentpack-memory/src/retrieval/tokenizer.ts) 用零依赖的方式同时处理中英文：

### 4.1 两种分词策略

| 语言 | 策略 | 示例 |
|------|------|------|
| Latin（英文） | 小写化 + 按非字母数字分割 | `"React-18!"` -> `["react", "18"]` |
| CJK（中文） | 逐字符成 token | `"我喜欢React"` -> `["我", "喜", "欢", "react"]` |

```typescript
export function tokenize(text: string): string[] {
  const tokens: string[] = [];
  let latinBuf = '';

  const flushLatin = () => {
    if (latinBuf) {
      const parts = latinBuf.toLowerCase().match(/[a-z0-9]+/g);
      if (parts) tokens.push(...parts);
      latinBuf = '';
    }
  };

  for (const ch of text) {
    if (isCJK(ch)) {          // 中文字符
      flushLatin();
      tokens.push(ch);        // 逐字成 token
    } else if (isCJKSymbol(ch)) {  // 中文标点
      flushLatin();           // 当分隔符
    } else {
      latinBuf += ch;         // 累积英文
    }
  }
  flushLatin();
  return tokens;
}
```

### 4.2 为什么中文逐字分词

中文没有空格分隔，也不像英文那样有成熟的词边界识别。在记忆检索场景下：

- 逐字分词实现简单、零依赖
- BM25 的 IDF 天然会降低高频单字（「的」「了」「是」）的权重
- 对短文本（记忆条目通常几十到几百字）效果够用

```
"用户偏好深色主题" -> ["用", "户", "偏", "好", "深", "色", "主", "题"]

query "主题偏好" -> ["主", "题", "偏", "好"]
命中 4 个 token，IDF 加权后得分高
```

### 4.3 停用词过滤

分词器还提供 `extractConcepts` 函数，用于从文本中提取关键词标签。它会在分词后过滤停用词：

```typescript
export const STOPWORDS = new Set<string>([
  // 英文
  'the', 'a', 'an', 'and', 'or', 'is', 'are', 'to', 'in', 'on', ...
  // 中文高频虚词
  '的', '了', '是', '在', '我', '你', '他', '这', '那', '和', ...
]);

export function extractConcepts(text: string, maxConcepts = 8): string[] {
  const tokens = tokenize(text);
  const freq = new Map<string, number>();
  for (const t of tokens) {
    if (STOPWORDS.has(t)) continue;         // 去停用词
    if (t.length < 2 && !isCJK(t)) continue; // 单字符英文跳过
    freq.set(t, (freq.get(t) ?? 0) + 1);
  }
  // 返回频次 top-N
  return [...freq.entries()]
    .sort((a, b) => b[1] - a[1])
    .slice(0, maxConcepts)
    .map(([t]) => t);
}
```

注意：**BM25 索引本身不去停用词**，保留所有词的 IDF 权重。停用词只用于概念抽取（给记忆打标签），两个用途不同。

## 五、分数归一化

BM25 的原始分数范围不固定（取决于 IDF 和文档集合），不同查询之间的分数不可比。agentpack-memory 在 [hybrid-retriever.ts](file:///Users/kye/Documents/ai/agentpack/packages/agentpack-memory/src/retrieval/hybrid-retriever.ts) 中用 min-max 归一化把分数映射到 0-1 区间：

```typescript
// 纯 BM25 模式
const scores = bm25Results.map((r) => r.score);
const normed = minMaxNormalize(scores);
// normed[i] = (score[i] - min) / (max - min)

return bm25Results
  .map((r, i) => ({ entry: r.entry, score: normed[i], matchedBy: 'bm25' }))
  .filter((r) => r.score >= this.minScore)  // 过滤低分
  .sort((a, b) => b.score - a.score)
  .slice(0, limit);
```

归一化后可以用统一的 `minScore` 阈值（默认 0.1）过滤低质量结果。

## 六、参数调优指南

| 参数 | 默认 | 作用 | 调优建议 |
|------|------|------|---------|
| k1 | 1.5 | 词频饱和速度 | 值大 = 词频更重要；值小 = 一次命中就够了 |
| b | 0.75 | 长度归一化强度 | 0 = 不考虑长度；1 = 完全按长度惩罚 |
| minScore | 0.1 | 最低分数阈值 | 值大 = 只留最相关的；值小 = 召回更多 |

经验值：

- **k1 = 1.2 ~ 2.0** 是大多数场景的最佳区间，1.5 是经典默认值
- **b = 0.75** 是学术验证的最优值，一般不用改
- 如果文档长度差异不大，可以降低 b 到 0.5 甚至 0
- 如果文档都很短（如记忆条目），b 影响不大

## 七、BM25 vs 其他检索方案

| 方案 | 优势 | 劣势 | 适用场景 |
|------|------|------|---------|
| **BM25** | 零依赖、速度快、关键词精确匹配 | 不理解语义 | 关键词检索、记忆系统 |
| **向量检索** | 语义相似（「开心」≈「快乐」） | 需 embedding 模型、精确匹配弱 | 语义搜索、问答系统 |
| **混合检索** | 兼顾关键词与语义 | 实现复杂 | 生产级 RAG 系统 |

agentpack-memory 的策略是**渐进增强**：默认 BM25（零依赖），配置 embedder 后自动升级为混合检索：

```
BM25 取 limit×3 候选
    ↓
query 与候选算 cosine 相似度
    ↓
两路分数 min-max 归一化
    ↓
加权融合：final = w_bm25 × bm25_norm + w_embed × cos_norm
```

## 八、总结

BM25 的精妙之处在于用极简的数学公式，把信息检索的三个核心要素融合在一起：

```
IDF  -> 词有多重要（稀有度）
TF   -> 词出现多频繁（饱和增长）
DLN  -> 文档有多长（长度惩罚）
```

配合倒排索引，BM25 能在 O(命中文档数) 的时间复杂度内完成检索，而不是 O(文档总数)。这也是为什么它至今仍是 Elasticsearch、Lucene 等搜索引擎的默认算法--简单、高效、效果好。

agentpack-memory 用不到 150 行零依赖代码实现了完整的 BM25 倒排索引，加上 CJK 分词和 min-max 归一化，让它能开箱即用地服务于 Agent 记忆检索场景。
